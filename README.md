# Palate

**Your food memory. Your kitchen. Your taste.**

A personal food operating system: it remembers what you like, what your cook can make, what's in the kitchen and where you loved eating, then helps you decide what to eat, send it to your cook, and shop for it.

## What works today (v0)

| Screen | What it does |
|---|---|
| **Today** | Suggests what to eat for breakfast, lunch or dinner, ranked by your rating, how long since you last had it, and what's in the kitchen. Shows what's on the menu, and fresh things to use soon. |
| **Make this** | Builds a WhatsApp message for your cook (dish, ingredients, recipe link, your instructions) in English or Hinglish, opens WhatsApp, and puts the dish on the menu. |
| **Cook** | Library of home dishes: *Can make*, *To learn*, *Want to try*, favourites; veg / egg / non-veg; ingredients, links, cook time, tags, rating, and meal history. **Archive** hides a dish from suggestions and lists but keeps its history. |
| **Dish ideas** | About 150 popular vegetarian dishes, Indian and international, with ingredients and a recipe video filled in. Tick several and add them in one go as *Can make*, *To learn* or *Want to try*. |
| **Recipe videos** | Each dish shows its YouTube video, the ingredients as used in that video, and a short step-by-step method summarised from it. The video link also goes in the WhatsApp message to your cook. Videos come from a list of recommended creators (Ranveer Brar, Your Food Lab, Kunal Kapur, Nisha Madhulika, Hebbars Kitchen and others, in `js/creators.js`), and each dish page links to searches on the creators best suited to it. |
| **Buy ingredients** | Each dish has a “Buy all ingredients on Amazon” button (one link with the whole list) and, beside it, “Buy missing ingredients”: the same kind of link with only what isn’t in your kitchen. Each ingredient also has its own Buy link. Anything the lists couldn’t include is shown with its own link. The links carry an Amazon Associates tag, and the site shows the required disclosure. |
| **Kitchen** | Lightweight pantry (staples / fresh / special, each have → low → out) and a shopping list worked out automatically from the menu and anything running low. Share it on WhatsApp. |
| **Out** | Restaurants you've been to and want to try, with dish-level ratings, *reorder* / *skip*, notes, area, who recommended it. **Make at home** sends a loved dish to your cook's *to learn* list. |
| **Memory** | Search everything ("that pizza I loved", "places around GK") plus insights: favourites, not had in a while, home vs. out, cuisines, regulars, still to try. |
| **＋ Save** | Save a recipe, reel or restaurant for later: paste a link, or on Android share straight into Palate from Instagram, YouTube or Maps once it's installed. Also opens from `…/palate/?url=<link>&title=<title>` or the bookmarklet in Settings. |

## On your phone

Palate is a Progressive Web App (PWA): a website you can install like an app.

- **Android (Chrome):** open the site, then tap **Install** on the banner, or **Settings → Install app**. It gets a home-screen icon, opens full screen and works offline. It also appears in the phone's **Share** menu, so you can send reels, recipes and map links straight to it.
- **iPhone (Safari):** tap **Share → Add to Home Screen**; Settings shows the steps. iOS doesn't let web apps receive shares, so copy the link and tap **＋** in Palate instead. The home-screen app keeps its **own copy** of your data, separate from Safari, so export and import a backup if you started in Safari.
- Long-pressing the app icon (Android) gives shortcuts to Today, the shopping list and Save.

Offline support comes from `sw.js` (network first, falling back to a cache). If you add a new JS or CSS file, add it to the `SHELL` list there too. The icons in `icons/` are generated by `python scripts/make-icons.py`.

## Your data

Everything is stored in your browser's `localStorage` on that device. Your food data is never sent anywhere, and nothing personal ever lands in this repo. That means:

- Data doesn't sync between your phone and laptop yet. Use **Settings → Export / Import backup** to move it.
- Export a backup now and then. Clearing site data wipes it. On iPhone, Safari can clear data for sites you haven't opened in a while; installing Palate on the Home Screen avoids that.

The site does count anonymous visits with [GoatCounter](https://www.goatcounter.com): no cookies, and nothing you enter in Palate. That count is the small "N visitors" line at the bottom of the page.

## Run it locally

No build step and no dependencies. Serve the folder with any static server (ES modules don't load from `file://`):

```bash
python -m http.server 8321
```

Then open <http://localhost:8321>. On the welcome screen, **Explore with sample data** fills it with an example household.

## Deploy to GitHub Pages

1. Push to `main`.
2. On GitHub, open **Settings → Pages**, then under **Build and deployment** choose **Deploy from a branch**, branch `main`, folder `/ (root)`.
3. The site appears at `https://<username>.github.io/palate/`.

GitHub Pages is free for public repos. For a private repo it needs a paid plan. Either way, your food data stays in your browser, not in the repo.

## How the code is laid out

```
index.html            page shell: top bar, tab bar, dialog, toast
manifest.webmanifest  app name, icons, home-screen shortcuts, share target
sw.js                 service worker: offline cache
css/styles.css        all styles; light + dark via CSS variables; touch rules at the end
js/app.js             hash router + event delegation (data-action / data-form / data-input / data-change)
js/store.js           the data model, localStorage persistence, update()
js/logic.js           ingredient matching, recommendations, shopping list, WhatsApp text, search, insights
js/modals.js          add/edit forms, "Make this", save-for-later, shared actions
js/pwa.js             install prompt and the home-screen tip
js/visitor-count.js   the "N visitors" footnote (GoatCounter; the beacon tag is at the end of index.html)
js/catalog.js         popular vegetarian dishes for Dish ideas, with their recipe videos
js/creators.js        recommended YouTube creators, and which suit which cuisine
js/recipes.js         ingredients and short methods taken from each recipe video
js/shop-links.js      Amazon links per ingredient and per dish (generated, see below)
js/diet.js            veg / egg / non-veg, guessed from name and ingredients
js/views/*.js         one module per screen; each exports render() and its handlers
js/sample.js          sample data (built from the catalogue)
scripts/make-icons.py regenerates icons/*.png
scripts/check-sw.mjs  checks the service worker never caches the analytics beacon (node scripts/check-sw.mjs)
scripts/build-shop-links.py  turns links/*.csv into js/shop-links.js
```

The Amazon link sheets live in `links/` (git-ignored). After editing them, run `python scripts/build-shop-links.py` and commit the regenerated `js/shop-links.js`; the site reads that file, not the CSVs.

Views return HTML strings built with a small `html` tagged template that escapes every value. The data model is documented at the top of `js/store.js`.

## Roadmap ideas

- **Sync:** the same data on phone and laptop (and for anyone else in the household).
- **AI layer:** paste a reel or recipe link and get the dish, ingredients and steps extracted; ask questions in plain language; smarter weekly planning. This needs a small server-side piece to keep an API key safe.
- **Learning patterns:** predict when staples will run out; suggest a weekly grocery list.
